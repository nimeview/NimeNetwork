NimeNetwork

NimeNetwork — это приватная сетевая платформа поверх innernet.

Проект состоит из двух слоёв:

  1. Базовая сеть
    • innernet-server и innernet
    • mesh IP-адресация
    • peer membership
    • invitations
  2. Сервисный слой
    • nime-registry — реестр сервисов и HTTP API
    • nime-dns — внутренний DNS
    • nime-portal — общая стартовая страница и поиск
    • nime-client — клиентский CLI
    • services/ — отдельные прикладные сервисы сети

Эта книга объясняет:

  • как собрать проект
  • как поднять сервер
  • как подключить клиента
  • как работают DNS, registry и portal
  • как регистрировать сервисы
  • как запускать встроенные wiki, storage и ledger
  • как диагностировать типовые проблемы

Быстрый ориентир по репозиторию

  • client/ — CLI для участника сети
  • server/dns/ — внутренний DNS
  • server/registry/ — реестр сервисов
  • server/portal/ — портал
  • server/innernet/ — vendored innernet
  • services/ — отдельные сервисы поверх сети
  • scripts/ — helper-скрипты для сервера и релизов

Архитектура

Базовая идея

NimeNetwork не заменяет innernet, а строится поверх него.

innernet отвечает за:

  • WireGuard-интерфейс
  • mesh-сеть
  • peers
  • invitations
  • ACL и топологию сети

Nime отвечает за:

  • DNS-имена сервисов
  • реестр сервисов
  • портал
  • клиентский UX
  • прикладные сервисы сети

Основные компоненты

innernet-server

Единая точка управления самой сетью:

  • создаёт сеть
  • хранит базу peers/CIDR
  • выдаёт invitations
  • принимает redeem от клиентов

nime-registry

Хранит сервисы:

  • name
  • group
  • target_ip
  • port
  • protocol
  • title
  • description
  • owner
  • tags

Также поднимает HTTP API, через которое остальные компоненты получают сервисные данные.

nime-dns

Внутренний authoritative DNS.

Источники данных:

  • peers из innernet.db
  • сервисы из nime-registry API

nime-portal

Стартовая страница сети:

  • поиск сервисов
  • человекочитаемые карточки
  • внутренние ссылки

nime-client

CLI для участника сети:

  • подключение
  • переподключение
  • DNS-конфиг
  • список сервисов
  • health-check
  • open в браузере

Как течёт информация

Поток данных выглядит так:

  1. Администратор запускает или публикует сервис
  2. Администратор добавляет запись в nime-registry
  3. nime-registry API начинает отдавать сервис
  4. nime-dns перечитывает API и публикует DNS-имя
  5. nime-portal показывает сервис в UI
  6. nime-client services видит этот сервис

Схема имён

Канонический вид имени сервиса:

<service>.<group>.nime.internal

Примеры:

  • portal.core.nime.internal
  • wiki.docs.nime.internal
  • drive.apps.nime.internal
  • ledger.apps.nime.internal

Если имя сервиса уникально во всей зоне, DNS может также выдать короткий алиас:

<service>.nime.internal

Но опираться лучше именно на каноническое имя с группой.

Почему группы важны

Группы решают несколько задач:

  • убирают коллизии имён
  • дают структуру зоне
  • позволяют строить понятную навигацию
  • упрощают рост сети

Рекомендуемые группы:

  • core — базовые системные сервисы сети
  • apps — обычные приложения
  • docs — документация и knowledge base
  • infra — админка, мониторинг, служебные панели
  • media — галереи, музыка, видео
  • dev — git, CI, registry, dev tools
  • personal — личные сервисы участников

Быстрый Старт

Ниже самый короткий рабочий путь для запуска сети и первого клиента.

Сервер

Предположения:

  • репозиторий: ~/NimeNetwork
  • имя сети: nimenet
  • mesh IP сервера: 10.42.0.1
  • зона DNS: nime.internal

1. Установить зависимости и собрать проект

cd ~/NimeNetwork
scripts/nime-server-linux.sh install-deps
scripts/nime-server-linux.sh build

2. Создать сеть innernet

cd ~/NimeNetwork/server/innernet
sudo target/release/innernet-server new

Во время мастера задай хотя бы:

  • Network name: nimenet
  • Network CIDR: 10.42.0.0/16
  • Listen port: 51820
  • External endpoint: внешний адрес сервера

После этого запомни путь к базе, например:

/var/lib/innernet-server/nimenet.db

3. Создать пользовательский CIDR

cd ~/NimeNetwork/server/innernet
sudo target/release/innernet-server add-cidr nimenet

Типовой вариант:

  • parent: nimenet
  • name: folks
  • cidr: 10.42.1.0/24

4. Запустить сервер сети

cd ~/NimeNetwork
sudo ./server/innernet/target/release/innernet-server serve nimenet

5. Создать invitation

cd ~/NimeNetwork/server/innernet
sudo target/release/innernet-server add-peer nimenet

При создании peer:

  • выбери CIDR folks
  • укажи имя клиента
  • сохрани invitation в .toml файл

6. Запустить registry, DNS и portal

cd ~/NimeNetwork
scripts/nime-server-linux.sh bootstrap-registry \
  --portal-ip 10.42.0.1 \
  --portal-port 8080 \
  --owner nime

cargo run -p nime-registry -- serve --bind 0.0.0.0:4172
cargo run -p nime-dns -- --bind 0.0.0.0:5354 --zone nime.internal --innernet-db /var/lib/innernet-server/nimenet.db --registry-api 127.0.0.1:4172
cargo run -p nime-portal -- --bind 0.0.0.0:8080 --registry-api 127.0.0.1:4172 --dns-zone nime.internal

Клиент

Предположения:

  • репозиторий: /Users/arthur/Documents/Project/NimeNetwork
  • invitation уже скопирован на клиентскую машину

1. Собрать innernet

cd /Users/arthur/Documents/Project/NimeNetwork/server/innernet
cargo build --release --bin innernet

2. Инициализировать nime-client

cd /Users/arthur/Documents/Project/NimeNetwork
cargo run -p nime-client -- init \
  --network nime \
  --innernet-network nimenet \
  --dns-server 10.42.0.1:5354 \
  --dns-zone nime.internal \
  --innernet-bin /Users/arthur/Documents/Project/NimeNetwork/server/innernet/target/release/innernet

3. Подключиться

cd /Users/arthur/Documents/Project/NimeNetwork
cargo build --release -p nime-client
sudo ./target/release/nime-client setup --invite invitation.toml

4. Проверить

cargo run -p nime-client -- services
cargo run -p nime-client -- open portal.core --port 8080

Сервер

Этот раздел про Linux-машину, где живёт сеть.

Что держит сервер

Сервер обычно хранит:

  • innernet-server
  • nime-registry
  • nime-dns
  • nime-portal
  • встроенные сервисы из services/

Развёртывание innernet-server с нуля

Этот сценарий нужен для полностью чистого Linux-сервера, где ещё нет готовой сети.

Предположения:

  • репозиторий лежит в ~/NimeNetwork
  • имя сети будет nimenet
  • mesh-сеть будет 10.42.0.0/16
  • пользовательский CIDR будет 10.42.1.0/24
  • внешний endpoint сервера будет доступен клиентам

1. Установить зависимости и собрать бинарники

cd ~/NimeNetwork
scripts/nime-server-linux.sh install-deps
scripts/nime-server-linux.sh build

2. Создать сеть

cd ~/NimeNetwork/server/innernet
sudo target/release/innernet-server new

Во время мастера обычно вводятся такие значения:

  • Network name: nimenet
  • Network CIDR: 10.42.0.0/16
  • Listen port: 51820
  • External endpoint: внешний IP или домен сервера, например 203.0.113.10:51820

После этого innernet-server создаст базу и напечатает путь, обычно:

/var/lib/innernet-server/nimenet.db

3. Создать пользовательский CIDR

Сразу после new сеть содержит только служебный серверный peer. Для обычных клиентов нужен отдельный CIDR.

cd ~/NimeNetwork/server/innernet
sudo target/release/innernet-server add-cidr nimenet

Типовые ответы:

  • Parent CIDR: nimenet
  • Name: folks
  • CIDR: 10.42.1.0/24

Если потом понадобятся отдельные сетевые зоны под сервисы или инфраструктуру, можно создавать новые CIDR отдельно.

4. Запустить сервер сети

В foreground:

cd ~/NimeNetwork
sudo ./server/innernet/target/release/innernet-server serve nimenet

В background:

cd ~/NimeNetwork
nohup sudo ./server/innernet/target/release/innernet-server serve nimenet > /root/innernet-server.log 2>&1 &

Проверка:

ps aux | grep innernet-server
tail -f /root/innernet-server.log

5. Создать первый peer и invitation

cd ~/NimeNetwork/server/innernet
sudo target/release/innernet-server add-peer nimenet

Обычно мастер спросит:

  • Eligible CIDRs for peer
  • IP
  • Name
  • Make <peer> an admin?
  • Invite expires after
  • Save peer invitation file to

Типовой пример:

  • CIDR: folks
  • IP: 10.42.1.1
  • Name: arthur-mac
  • admin: yes или no по задаче
  • expiration: 14d
  • invitation file: /root/invitations/arthur-mac.toml

Именно этот файл потом передаётся клиенту.

6. Настроить автозапуск innernet-server

Если сеть уже проверена вручную, лучше сразу включить systemd unit:

sudo systemctl enable --now innernet-server@nimenet

Проверка:

systemctl status innernet-server@nimenet

7. Только после этого поднимать nime-*

Когда innernet-server уже живой, можно переходить к:

  • nime-registry
  • nime-dns
  • nime-portal
  • сервисам из services/

Где лежат важные данные

База innernet

Обычно:

/var/lib/innernet-server/nimenet.db

База registry

Обычно:

server/registry/nime-registry.db

Данные встроенных сервисов

Обычно:

  • services/data/wiki/
  • services/data/storage/
  • services/data/ledger/

Ручной запуск основных компонентов

innernet-server

Foreground:

cd ~/NimeNetwork
sudo ./server/innernet/target/release/innernet-server serve nimenet

Background:

cd ~/NimeNetwork
nohup sudo ./server/innernet/target/release/innernet-server serve nimenet > /root/innernet-server.log 2>&1 &

nime-registry API

cd ~/NimeNetwork
cargo run -p nime-registry -- serve --bind 0.0.0.0:4172

nime-dns

cd ~/NimeNetwork
cargo run -p nime-dns -- \
  --bind 0.0.0.0:5354 \
  --zone nime.internal \
  --innernet-db /var/lib/innernet-server/nimenet.db \
  --registry-api 127.0.0.1:4172

nime-portal

cd ~/NimeNetwork
cargo run -p nime-portal -- \
  --bind 0.0.0.0:8080 \
  --registry-api 127.0.0.1:4172 \
  --dns-zone nime.internal

Создание invitation

Invitation создаётся так:

cd ~/NimeNetwork/server/innernet
sudo target/release/innernet-server add-peer nimenet

Команда спросит, куда сохранить файл.

Например:

/root/invitations/arthur-client.toml

Именно этот файл нужно передать клиенту.

Для nime-* уже есть helper:

cd ~/NimeNetwork
scripts/nime-server-linux.sh install-units \

Это ставит:

  • nime-registry-api.service
  • nime-dns.service
  • nime-portal.service

innernet-server можно также включить отдельно:

sudo systemctl enable --now innernet-server@nimenet

После перезагрузки сервера

Проверь:

Или через systemd:

Клиент

Этот раздел для участника сети.

Что нужно клиенту

  • invitation-файл от администратора
  • собранный innernet
  • nime-client
  • wireguard-go на macOS, если он не встроен в систему

Первичная настройка

cargo run -p nime-client -- init \
  --network nime \
  --innernet-network nimenet \
  --dns-server 10.42.0.1:5354 \
  --dns-zone nime.internal \
  --innernet-bin /absolute/path/to/innernet

После этого в конфиг записываются:

  • имя клиента
  • имя innernet сети
  • адрес DNS
  • зона
  • путь к innernet

Первое подключение

sudo ./target/release/nime-client setup --invite invitation.toml

Команда делает:

  • innernet install
  • innernet up
  • innernet fetch
  • установку DNS-конфига

Ежедневные команды

Показать сервисы:

cargo run -p nime-client -- services

Проверить peer:

cargo run -p nime-client -- health --peer laptop --port 22

Проверить сервис:

cargo run -p nime-client -- health wiki.docs

Открыть сервис:

cargo run -p nime-client -- open wiki.docs --port 8181

Показать конфиг:

cargo run -p nime-client -- show-config

После перезагрузки

sudo ./target/release/nime-client reconnect

Если команда пишет, что не найден innernet, проверь:

cargo run -p nime-client -- show-config

И убедись, что innernet_binary указывает на реальный абсолютный путь.

Отключение

sudo ./target/release/nime-client disconnect

Если DNS надо оставить:

sudo ./target/release/nime-client disconnect --keep-dns

Автозапуск клиента

macOS:

sudo ./target/release/nime-client autostart-install --format launchd

Linux user service:

./target/release/nime-client autostart-install --format systemd-user

DNS И Имена

Базовая зона

Сейчас проект использует одну внутреннюю зону:

nime.internal

Имена peers

Peers приходят из innernet.db и публикуются как:

<peer>.nime.internal

Пример:

nimenet.nime.internal

Имена сервисов

Канонический вид:

<service>.<group>.nime.internal

Примеры:

  • portal.core.nime.internal
  • wiki.docs.nime.internal
  • drive.apps.nime.internal
  • ledger.apps.nime.internal

Короткие алиасы

Если имя сервиса уникально во всей зоне, nime-dns дополнительно публикует:

<service>.nime.internal

Но это только алиас. Надёжнее всегда использовать полное имя с группой.

Почему не делать фейковые TLD

Имена вроде:

  • example.nime
  • example.os

смотрятся красиво, но неудобны как базовая архитектура, потому что:

  • могут конфликтовать позже
  • хуже сочетаются с реальными резолверами
  • усложняют перенос проекта

Поэтому проект строится на одной canonical zone, а группы живут внутри неё.

Как проверить DNS

Явный запрос к серверу DNS:

dig @10.42.0.1 -p 5354 wiki.docs.nime.internal

Через клиент:

cargo run -p nime-client -- resolve wiki.docs

Что делает nime-dns

  • читает peers из innernet.db
  • читает сервисы через nime-registry API
  • отвечает A-записями
  • умеет reload без рестарта

Registry И Публикация Сервисов

Зачем нужен registry

Запуск приложения ещё не делает его частью сети.

Чтобы сервис появился в Nime, нужно:

  1. Запустить приложение
  2. Добавить его в nime-registry
  3. Дождаться, пока nime-dns и nime-portal его увидят

Минимальная модель сервиса

У сервиса есть:

  • name
  • group
  • target_ip
  • port
  • protocol
  • title
  • description
  • owner
  • tags

Добавление сервиса

Пример:

cd ~/NimeNetwork
cargo run -p nime-registry -- add \
  --db server/registry/nime-registry.db \
  --name blog \
  --group apps \
  --target-ip 10.42.0.1 \
  --port 3000 \
  --proto http \
  --title "Blog" \
  --description "Внутренний блог" \
  --owner nime \
  --tags web,shared

Это создаст каноническое имя:

blog.apps.nime.internal

Обновление сервиса

cargo run -p nime-registry -- update \
  --db server/registry/nime-registry.db \
  --name blog \
  --port 4000 \
  --description "Новый порт"

Можно менять:

  • группу
  • IP
  • порт
  • title
  • owner
  • tags

Просмотр сервисов

cargo run -p nime-registry -- list
cargo run -p nime-registry -- get --name blog

Registry API

Запуск:

cargo run -p nime-registry -- serve --bind 0.0.0.0:4172

Endpoints:

  • GET /health
  • GET /services
  • GET /services?q=wiki
  • GET /services/<name>

Практические правила

  • используй mesh IP, а не публичный IP
  • не регистрируй сервис, пока он реально не слушает порт
  • owner для встроенных сервисов можно держать как nime
  • короткие и стабильные имена предпочтительнее

Рекомендуемые группы

  • core
  • apps
  • docs
  • infra
  • media
  • dev
  • personal

Встроенные Сервисы

В проекте есть отдельная папка services/ для прикладных сервисов сети.

Это важно: они не встроены в саму сетевую логику, а живут отдельно поверх неё.

Что уже есть

Wiki

Сервис:

  • crate: nime-wiki
  • порт: 8181
  • DNS: wiki.docs.nime.internal

Назначение:

  • общая страница сети
  • документация
  • заметки и правила

Storage

Сервис:

  • crate: nime-storage
  • порт: 8282
  • DNS: drive.apps.nime.internal

Назначение:

  • общее файловое хранилище
  • архивы, документы, установщики

Ledger

Сервис:

  • crate: nime-ledger
  • порт: 8383
  • DNS: ledger.apps.nime.internal

Назначение:

  • внутренняя игровая валюта сети
  • ограниченный выпуск
  • без связи с реальными деньгами
  • без внешней стоимости

Это не банк и не платёжная система.

Запуск всех встроенных сервисов

cd ~/NimeNetwork
services/run-all.sh start
services/run-all.sh status

Остановка:

services/run-all.sh stop

Регистрация встроенных сервисов

cd ~/NimeNetwork
services/register-defaults.sh --server-ip 10.42.0.1

Это создаст записи в registry для:

  • wiki.docs
  • drive.apps
  • ledger.apps

Где лежат данные

  • wiki: services/data/wiki
  • storage: services/data/storage
  • ledger: services/data/ledger/state.json

Как открыть

Через браузер:

  • http://wiki.docs.nime.internal:8181
  • http://drive.apps.nime.internal:8282
  • http://ledger.apps.nime.internal:8383

Через клиент:

cargo run -p nime-client -- open wiki.docs --port 8181
cargo run -p nime-client -- open drive.apps --port 8282
cargo run -p nime-client -- open ledger.apps --port 8383

Ежедневная Работа

Для администратора

Типовой цикл:

  1. Проверить, что сервер сети поднят
  2. Проверить registry, dns, portal
  3. При необходимости выдать invitation
  4. Поднять прикладные сервисы
  5. Зарегистрировать новые сервисы

Команды:

ps aux | grep innernet-server
ps aux | grep nime-registry
ps aux | grep nime-dns
ps aux | grep nime-portal
services/run-all.sh status

Для обычного клиента

Типовой цикл:

  1. Переподключиться после перезагрузки
  2. Посмотреть список сервисов
  3. Открыть нужный сервис

Команды:

sudo ./target/release/nime-client reconnect
cargo run -p nime-client -- services
cargo run -p nime-client -- open portal.core --port 8080

Проверка состояния сети

Peers:

sudo ./target/release/nime-client peers --tree

DNS:

cargo run -p nime-client -- resolve wiki.docs

Health:

cargo run -p nime-client -- health wiki.docs
cargo run -p nime-client -- health --peer nimenet --port 22

Когда что использовать

setup

Только при первом подключении по invitation.

reconnect

После перезагрузки клиента или после ручного обрыва.

disconnect

Когда надо полностью отцепить клиента от сети.

services

Когда нужно быстро понять, что вообще доступно в сети.

open

Когда нужно открыть сервис в браузере без ручного набора URL.

Диагностика И Типовые Проблемы

nime-client services пишет timeout к 10.42.0.1:4172

Скорее всего:

  • не запущен nime-registry API
  • не поднят innernet-server
  • клиентский интерфейс не переподнят после перезагрузки

Проверка на клиенте:

sudo ./target/release/nime-client peers --tree
sudo ./target/release/nime-client reconnect

Проверка на сервере:

ps aux | grep innernet-server
ps aux | grep nime-registry

innernet-server не запускается через sudo

Если в логе:

sudo: server/innernet/target/release/innernet-server: command not found

значит путь был указан без ./.

Правильно:

sudo ./server/innernet/target/release/innernet-server serve nimenet

nime-client reconnect не находит innernet

Проверь:

cargo run -p nime-client -- show-config

Если innernet_binary=innernet, а бинарник не лежит в PATH, переинициализируй клиент с абсолютным путём.

dig portal... идёт в 1.1.1.1

Это не обязательно ошибка самой сети. dig по умолчанию может идти в системный внешний resolver.

Для проверки внутреннего DNS лучше явно указывать сервер:

dig @10.42.0.1 -p 5354 portal.core.nime.internal

Имя сервиса не открывается, хотя DNS резолвится

Значит чаще всего:

  • сервис не слушает нужный порт
  • bind address не тот
  • приложение поднято только на 127.0.0.1
  • неверный порт в registry

Проверь на сервере:

curl http://127.0.0.1:<port>/health

После перезагрузки сервера всё “сломалось”

Обычно это значит, что:

  • innernet-server не включён в автозапуск
  • nime-* сервисы не поставлены как systemd units

Решение:

scripts/nime-server-linux.sh install-units --innernet-db /var/lib/innernet-server/nimenet.db
sudo systemctl enable --now innernet-server@nimenet

Релизы И Упаковка

Зачем нужны релизы

Пока проект можно использовать прямо из исходников, но release-архивы позволяют:

  • не таскать весь репозиторий на прод
  • раздавать клиентский пакет отдельно
  • быстрее ставить серверный набор

Сборка release-пакетов

scripts/package-release.sh

С версией:

scripts/package-release.sh --version 0.1.1

Если сборка уже сделана:

scripts/package-release.sh --skip-build

Что входит в клиентский архив

  • nime-client
  • innernet
  • quickstart
  • user guide
  • install script

Что входит в серверный архив

  • nime-dns
  • nime-portal
  • nime-registry
  • innernet-server
  • server helper script
  • admin docs
  • runbook
  • install script

Что ещё можно улучшить

  • автоматическая мультиплатформенная упаковка
