# Архитектура

## Базовая идея

`NimeNetwork` не заменяет `innernet`, а строится поверх него.

`innernet` отвечает за:

- WireGuard-интерфейс
- mesh-сеть
- peers
- invitations
- ACL и топологию сети

`Nime` отвечает за:

- DNS-имена сервисов
- реестр сервисов
- портал
- клиентский UX
- прикладные сервисы сети

## Основные компоненты

### `innernet-server`

Единая точка управления самой сетью:

- создаёт сеть
- хранит базу peers/CIDR
- выдаёт invitations
- принимает redeem от клиентов

### `nime-registry`

Хранит сервисы:

- `name`
- `group`
- `target_ip`
- `port`
- `protocol`
- `title`
- `description`
- `owner`
- `tags`

Также поднимает HTTP API, через которое остальные компоненты получают сервисные данные.

### `nime-dns`

Внутренний authoritative DNS.

Источники данных:

- peers из `innernet.db`
- сервисы из `nime-registry API`

### `nime-portal`

Стартовая страница сети:

- поиск сервисов
- человекочитаемые карточки
- внутренние ссылки

### `nime-client`

CLI для участника сети:

- подключение
- переподключение
- DNS-конфиг
- список сервисов
- health-check
- open в браузере

## Как течёт информация

Поток данных выглядит так:

1. Администратор запускает или публикует сервис
2. Администратор добавляет запись в `nime-registry`
3. `nime-registry API` начинает отдавать сервис
4. `nime-dns` перечитывает API и публикует DNS-имя
5. `nime-portal` показывает сервис в UI
6. `nime-client services` видит этот сервис

## Схема имён

Канонический вид имени сервиса:

```text
<service>.<group>.nime.internal
```

Примеры:

- `portal.core.nime.internal`
- `wiki.docs.nime.internal`
- `drive.apps.nime.internal`
- `ledger.apps.nime.internal`

Если имя сервиса уникально во всей зоне, DNS может также выдать короткий алиас:

```text
<service>.nime.internal
```

Но опираться лучше именно на каноническое имя с группой.

## Почему группы важны

Группы решают несколько задач:

- убирают коллизии имён
- дают структуру зоне
- позволяют строить понятную навигацию
- упрощают рост сети

Рекомендуемые группы:

- `core` — базовые системные сервисы сети
- `apps` — обычные приложения
- `docs` — документация и knowledge base
- `infra` — админка, мониторинг, служебные панели
- `media` — галереи, музыка, видео
- `dev` — git, CI, registry, dev tools
- `personal` — личные сервисы участников
